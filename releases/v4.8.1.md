# BagOfGold 4.8.1

BagOfGold 4.8.1 prevents offline economy changes from being overwritten by a
stale physical inventory and makes physical-money deductions atomic.

## Highlights

- Keeps the last physical inventory snapshot stable while Vault records offline
  deposits and withdrawals as pending changes.
- Applies pending changes to physical money before normal inventory
  reconciliation when the player reconnects.
- Preserves pending changes during inventory moves, pickups and rapid reconnects.
- Plans an exact deduction on cloned inventory contents before changing loose
  money, cursor items, bundles or carried shulker boxes.
- Claims all consumed signed tokens in one database transaction and aborts the
  complete deduction if any claim fails.
- Coalesces queued balance snapshots and flushes the latest player snapshot
  before a reconnect read.

## Compatibility

- Java 21.
- Paper 1.21.11 is the current validation target.
- CustomItemsLib 1.4.1 is required.
- MobHunting 8.8.0 is the validated companion release.
- Vault integrations such as Towny continue to use BagOfGold as their economy provider.

## Validation

- Automated tests cover offline balance policy, accumulated changes, debt
  settlement, snapshot coalescing and storage ordering.
- Loose and nested money, item movement, rapid reconnects and insufficient exact
  deductions were exercised on Paper 1.21.11.
- A live Towny daily tax cycle completed after deployment; accounts that later
  reconnected did not restore the withdrawn balance from their inventory.
- No pending-reconciliation, duplicate-token or storage-worker errors were
  observed during production validation.
